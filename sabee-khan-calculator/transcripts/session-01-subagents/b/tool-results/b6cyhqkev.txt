    31	## Decimal strategy (ADR-002)
    32	Every input becomes a **scaled integer** by string parsing (never `parseFloat`/`Number()` on the raw text):
    33	- `E` = marks earned × 100, `T` = total × 100 (≤ 2 dp, A-4) · `P` = pass mark × 10 (≤ 1 dp, A-6).
    34	- Parse: digits before the dot form the integer part, the fraction is right-padded to `maxDp` digits, `value = int × 10^maxDp + frac`.
    35	- **Saturation:** if the integer part (leading zeros stripped) has more than 9 digits, value = `OVER_LIMIT` (10^12). It is above every limit, so it can only produce a range or M-15 error and never reaches arithmetic.
    36	
    37	| Quantity | Exact formula (integers only) | Rounding |
    38	|----------|-------------------------------|----------|
    39	| Score in tenths of a percent | `s = floorDiv(E × 1000, T)`; shown as `⌊s/10⌋ + "." + s%10 + "%"` | down, 1 dp (A-3) |
    40	| Verdict | Pass ⇔ `E × 1000 ≥ P × T` (exact score, A-1, A-2) | none |
    41	| Gap numerator (marks × 10⁵) | `D = E × 1000 − P × T` | — |
    42	| Shortfall (D < 0), hundredths | `h = ceilDiv(−D, 1000)` → never 0, so under 0.01 shows "0.01" | up, 2 dp (A-10) |
    43	| Surplus (D > 0), hundredths | `h = floorDiv(D, 1000)`; h = 0 → M-11 | down, 2 dp (A-10) |
    44	| Equal (D = 0) | M-10 | — |
    45	| Future S-6: marks needed | `ceilDiv(P × T, 1000)` hundredths | up |
    46	
    47	**Magnitude:** max E = max T = 1,000,000.00 → 100,000,000; max P = 1000. Largest product: `E × 1000` ≤ 1.0 × 10¹¹ and `P × T` ≤ 1000 × 10⁸ = 1.0 × 10¹¹; |D| ≤ 1.0 × 10¹¹. `Number.MAX_SAFE_INTEGER` = 9,007,199,254,740,991 ≈ 9.0 × 10¹⁵, so the headroom is about 90,000×. All values are exact in `number`; BigInt is not needed. `%` and the exact-multiple division in `floorDiv` are exact for safe integers.

    67	- Score: always 1 dp, "%" suffix, range "0.0%".."100.0%" (no separators needed). Gap: `formatMarks(h)` = integer part with a comma every 3 digits (string regex, not `toLocaleString`/`Intl`, ADR-007), then "." + 2-digit fraction with trailing zeros trimmed ("0.60" → "0.6", "2.00" → "2"). Singular M-7/M-9 only when h = 100.

    70	## Validation (A-13..A-15)
    71	Accepted text after `trim()`: `^-?(\d+\.?\d*|\.\d+)$`; empty after trim → `value: null`. Per field, first failing check wins:
    72	
    73	| # | Check | Earned | Total | Pass mark |
    74	|---|-------|--------|-------|-----------|
    75	| 1 | Not a number (letters, ",", "$", "+", "e", 2+ dots, inner spaces, "-" without a valid number) | `NOT_NUMBER` → M-12 | M-16 | M-21 |
    76	| 2 | Leading "-" before a valid number, incl. "-0" (A-14) | `NEGATIVE` → M-13 | M-17 | M-22 |
    77	| 3 | Fraction digits as typed > max dp ("17.500" has 3) | `TOO_MANY_DP` → M-14 | M-18 | M-23 |
    78	| 4 | Range | — | `ZERO` → M-19 · `TOO_LARGE` → M-20 | `TOO_LARGE` → M-24 |
    79	| 5 | Earned > total, only when both pass 1–4 | `OVER_TOTAL` → M-15 (under earned) | — | — |
    80	
    81	- Codes are a TypeScript union per field; `messages.ts` maps `(field, code)` → M-ID text. Nothing throws to the UI.
    82	- Bare "." or "-" (Q-13, open): default = not a number (strict A-13 wording); one-line change if the PO prefers "treat as empty".

    84	## State model
    85	`toViewModel` is recomputed from the three raw strings on every event (no stored calculation state). Precedence top-down:
    86	
    87	| State | Condition | Result area | Fields |
    88	|-------|-----------|-------------|--------|
    89	| error | any field has an error | "!" + M-3; no score, verdict, gap (A-16) | each invalid field shows its own message, `aria-invalid="true"` |
    90	| idle | earned or total empty, no errors | M-1 | no messages |
    91	| pass-mark-empty | earned + total valid, pass empty | score + M-2 in the verdict slot; no gap (A-12) | no messages |
    92	| result | all three valid | score + verdict block (M-4/M-5) + gap line (M-6..M-11) | no messages |
    93	
    94	Transitions: idle → result/pass-mark-empty as the last value becomes valid · result → error on any invalid edit · error → recovery: the message clears on the edit that makes the field valid (M-15 re-checks when total changes) and the result returns at once (S-3.8) · any state → idle on Next learner / Escape. Reload → initial state (earned "", total "", pass "70"); inputs carry `autocomplete="off"` so Firefox does not restore values.

    96	## Interaction and accessibility
    97	- Inputs: `type="text" inputmode="decimal" autocomplete="off" spellcheck="false"` (ADR-003), `<label for>`, `aria-describedby` → error slot (always present), `aria-invalid` only while in error.
    98	- Live update on every `input` event (typing, paste, cut, autofill); no Calculate button (A-7). Visual update is immediate.
    99	- **Announcements:** accept the designer's 500 ms debounce, for the visually hidden `role="status"` node only; it announces only when the text differs from the last one. Content per ui-design.md §Accessibility. e2e waits with auto-retrying assertions, so tests stay deterministic.
   100	- Enter: the `<form>` `submit` is prevented and the button is `type="button"`, so Enter never reloads or changes values.
   101	- Next learner (A-17): click or Escape in marks earned only → earned = "", recompute (clears M-15 and any earned message), focus earned, announce M-1. Idempotent, so rapid clicks are safe. Escape in other fields does nothing. Button has `aria-keyshortcuts="Escape"`.
   102	- WCAG 2.2 AA: tokens from ui-design.md (contrast computed there), 44 × 44 targets, visible focus ring, icon + text for errors and verdict, `prefers-reduced-motion`, no horizontal scroll at 320 px; axe in e2e (ADR-006).

   105	| ADR | Decision | Alternatives considered | Reason |
   106	|-----|----------|-------------------------|--------|

# Deploy the built app to GitHub Pages (D3, DEC-17). The live URL is offered IN ADDITION to the local run.
# No secrets, no paid services. Vite `base: './'` (ADR-008) keeps asset paths relative for the Pages sub-path.
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    name: Build
    runs-on: ubuntu-latest
    timeout-minutes: 10
    defaults:
      run:
        working-directory: sabee-khan-calculator
    steps:
      - name: Check out
        uses: actions/checkout@v4

      - name: Set up Node from .nvmrc
        uses: actions/setup-node@v4
        with:
          node-version-file: sabee-khan-calculator/.nvmrc
          cache: npm
          cache-dependency-path: sabee-khan-calculator/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Configure Pages
        uses: actions/configure-pages@v5

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: sabee-khan-calculator/dist

  deploy:
    name: Deploy
    needs: build
    runs-on: ubuntu-latest
    timeout-minutes: 10
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
