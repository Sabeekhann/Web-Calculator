**Process (A)**
1. Work stage by stage. At every gate STOP, post a Gate Report, wait for "approved". Never skip ahead or approve on the PO's behalf.
2. No application code until Gate 5 is approved. Before that: documents, design files and configuration only.
3. Ambiguity → ask the PO. Approved assumptions go in the README Assumptions section; open questions go in `decision-log.md`.
4. Docs describe reality. "Implemented" only when every AC has a verified PASS from automated tests, the QA agent's independent check, and the PO's manual check where needed.

6. Never write, summarise, fabricate or edit a transcript.

8. Builder and checker are always different agents.
9. Subagents never spawn subagents; every delegation gets a Handoff Brief.
10. Review every agent's output before showing it to the PO; name issues fixed or sent back.
11. Every feature traces to a story, every story to a job, every job to a role.

## 10. UI/UX standards
- Filled in from the approved `ui-design.md` at Gate 4: tokens, type scale, spacing scale, component states, themes, breakpoints, motion.
- Fixed rules: WCAG 2.2 AA (text contrast ≥ 4.5:1), visible focus ring, 44×44px touch targets, aria-live for results and errors, aria-invalid + aria-describedby on fields in error, never colour alone for errors, respect prefers-reduced-motion, no horizontal scroll at 320px, light and dark themes, tabular numerals for results.
- Breakpoints: 375px (mobile), 768px (tablet), 1280px (desktop); layout checked at 320px for overflow.
- Motion: short and subtle (≈150–200ms, ease-out), disabled under prefers-reduced-motion; no animation delays a result.
- Styling only through design tokens (CSS custom properties in `tokens.css`); no hard-coded colours, sizes or shadows in components.
- **Visual review checklist**: alignment · spacing consistency · type hierarchy · contrast · focus states · error states · dark mode · mobile layout · number formatting · no layout shift when results or errors appear.

## 11. Technical standards
- Node 20 LTS (`.nvmrc`, `engines`), Vite, vanilla TypeScript (`strict: true`), Vitest, Playwright.
- No UI framework, no backend, no network calls, no external fonts or CDNs at runtime (system font stack or self-hosted).
- Architecture: logic (pure) → validation (typed results) → UI (DOM). UI never calculates; logic never touches the DOM.
- Decimal strategy: set by ADR in Stage 5; never show floating-point artefacts (e.g. 0.1 + 0.2 shows 0.3); rounding rules stated.
- Typed `{ ok: true, value } | { ok: false, code }` results; never throw to the UI.
- One message catalogue (`src/messages.ts`); UI text never hard-coded elsewhere.
- Output is never NaN, Infinity, undefined or blank.
- **State model**: idle → valid → result → error → recovery. Editing any input after a result recalculates or clears the stale result as the ACs say; an error clears as soon as the input becomes valid.
- **Error strategy**: validation returns an error code → UI looks up the text in `messages.ts` → shows it inline next to the field (aria-describedby) and announces it (aria-live) → no result is shown while an error is active.
- **Limits**: maximum/minimum values and decimal places are fixed per input in technical-design.md and quoted exactly in the ACs.
- Code style: small pure functions, descriptive names, no dead code, no `any`.

## 12. Testing standards
- Tests before code: write failing unit tests and e2e specs from the ACs, show them failing, then implement.
- Every AC maps to a T-ID, an E-ID, or MANUAL with a reason (test-plan.md).
- **Edge sweep**: empty, whitespace, letters, symbols, "1e400", "-0", multiple dots, leading zeros, negatives, 0, maximum allowed, very long input, pasted values (spaces, currency symbols), repeated Enter, rapid clicking, recovery after an error, page reload.
- **Browser matrix**: Chromium (≈ Chrome/Edge), Firefox, WebKit (≈ Safari) via Playwright; plus PO manual checks in real browsers.
- **QA report** (`qa-reports/S-x.md`) skeleton:


/// <reference types="vitest/config" />
import { defineConfig, type Plugin } from 'vite';
import { MESSAGES, type MessageId } from './src/messages';

/** Replaces %M-n% placeholders in index.html with catalogue text, so messages.ts stays the single source. */
function catalogueHtml(): Plugin {
  return {
    name: 'catalogue-html',
    transformIndexHtml(html) {
      return html.replace(/%(M-\d+)%/g, (placeholder, id: string) => {
        if (!(id in MESSAGES)) throw new Error(`index.html: unknown message ${placeholder}`);
        return escapeHtml(MESSAGES[id as MessageId]);
      });
    },
  };
}

function escapeHtml(text: string): string {
  return text.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;');
}

// ADR-008: relative base so the same build works from `vite preview` and any GitHub Pages sub-path.
export default defineConfig({
  base: './',
  plugins: [catalogueHtml()],
  build: {
    outDir: 'dist',
    emptyOutDir: true,
  },
  preview: {
    host: '127.0.0.1',
    port: 4173,
    strictPort: true,
  },
  // ADR-005: Vitest runs pure modules only, in the node environment.
  test: {
    environment: 'node',
    include: ['tests/unit/**/*.test.ts'],
  },
});
